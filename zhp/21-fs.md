## 一句话

**`ctx.fs` 提供结构化、可换后端的文件读写；策略（先读后写）与模型工具是旁路插件/Consumer，不绑死在基类上。** base 默认挂 `fs-sandbox` + `tool-fs` / `tool-fs-search`；observation-policy 默认 **disabled**。（源码）

## 1. 设计要点

- **约定高于机制**：seam 只命名能做什么（resolve / 读 / 写 / 编辑 / 补丁 / 删 / 移）；字节怎么存归后端。
- **策略不进基类**：先读后写、版本防护是 `fs-observation-policy` 经事件裁决；去掉策略 = 裸无条件变更，工具不坏。
- **`editText` 留在 seam**：版本校验、字面匹配、原子写同一临界区。
- **有界读**：`readBytes` 要 `maxBytes`，过大 `FS_TOO_LARGE`，不截断糊弄。
- **无 I/O deadline**：取消靠可选 `AbortSignal`；与 shell 的超时模型不同。

失败是稳定 `FsError` 码（如 `FS_NOT_FOUND`、`FS_STALE_VERSION`、`FS_SANDBOX_DENIED`），不靠解析英文消息。

## 2. `ctx.fs` API 面（概要）

先 `resolve(path, { cwd? })` → 不透明 `FsTarget`（`targetKey` / `version` 不可解析；展示用 `displayPath`），再：

| 类 | 方法 |
|---|---|
| 读 / 观察 | `stat` / `lstat` / `readText` / `streamText` / `readBytes` / `listDir` / `watch` |
| 变更 | `writeText` / `editText` / `patchText` / `deleteFile` / `moveFile` |

策略事件：`fs/write-intent`、`fs/edit-intent`、`fs/delete-intent`、`fs/observed`。

真源：[docs/subsystems/filesystem.zh.md](../docs/subsystems/filesystem.zh.md)。

## 3. 实现：local vs sandbox

### 3.1 fs-local

宿主文件；`config.cwd` 只是相对路径默认解析根，**不是**安全边界（绝对路径 / `..` 可逃逸）。监听用 Chokidar（OS 事件，不轮询）。

### 3.2 fs-sandbox（默认）

扩展 local：对 `writeText` / `editText` / `patchText` / `deleteFile` / `moveFile` 按会话 `sandboxPolicy` 围栏：

| 模式 | 变更 |
|---|---|
| `read-only` | 全拒 → `FS_SANDBOX_DENIED` |
| `workspace-write` | 仅工作区 / 额外可写根 / 平台 temp |
| `danger-full-access` | 不围栏 |

读、list、watch **不限**。围栏是**可信代码里对路径的检查**，不是内核隔离——不可信命令的硬边界仍归 shell（[17c](./17c-sandbox-local.md)）。与 bash 共用同一套策略根，避免两族约束不一致。

## 4. 使用：模型工具与调用链

### 4.1 tool-fs

| 工具 | 作用 |
|---|---|
| `read` | 带行号 UTF-8，有行/字节上限 |
| `read_image` | 需 `ctx.attachments` + 支持图的模型路由 |
| `write` / `edit` | 原子写 / 字面替换；有策略时要求先读且未陈旧 |
| `apply_patch` | 默认配置常关；base/standard 可开 |

相对路径跟 Session cwd；沙箱权限根仍由策略定。

### 4.2 改文件链路

```text
模型 read/write/edit
  → tool-fs
  →（可选）fs/*-intent ← observation-policy
  → ctx.fs.*
  → fs-sandbox 围栏 → fs-local 落盘
  → fs/observed
```

### 4.3 搜索链路（刻意不进 ctx.fs）

```text
glob / grep → tool-fs-search → ctx.subprocess.spawn(打包的 ripgrep)
```

不要求宿主机装 `rg`；不经 shell 层。

### 4.4 最小组合示意

```yaml
- name: '@deepseek-ai/dsh-sandbox-policy'
- name: '@deepseek-ai/dsh-fs-sandbox'
- name: '@deepseek-ai/dsh-tool-fs'
# 需要先读后写时：启用 fs-observation-policy（base 默认 disabled）
```

## 5. 与 shell / jobs / subprocess 边界

| | fs | shell |
|---|---|---|
| 接口 | 结构化 `ctx.fs` | 命令字符串 |
| 「沙箱」 | 路径写围栏（fs-sandbox） | runner profile（bwrap 等） |
| 超时 | 无 deadline | 有 |
| 后台 | 不进 jobs | 可登记 job |
